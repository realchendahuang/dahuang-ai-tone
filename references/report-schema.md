## 固定结构

```md
# 模型腔调风格审计报告

## 结论

最像的模型家族：{模型家族 / 无法判断}  
可能版本层级：{具体版本 / 家族级 / 证据不足}  
产品表面判断：{ChatGPT / Claude.ai / Perplexity 式检索回答 / API 输出 / 无法判断}  
置信度：低 / 中 / 高

一句话判断：{最重要的判断}

## 风格相似度

- {模型家族 A}：高 / 中 / 低  
  像在：{落到可观察形式的具体说明}
- {模型家族 B}：高 / 中 / 低  
  像在：{落到可观察形式的具体说明}

## 版本与产品表面说明

- {说明为什么不能或可以判断到版本——引用 `references/model-version-policy.md` 里的硬证据}
- {说明是否存在产品表面痕迹}

## 逐处证据

### 证据 1

> {引用原文片段}
```

## 写法要求

- 不输出模型来源结论。
- 不输出伪精确百分比。
- 不把 Perplexity 当模型家族（见 `references/model-version-policy.md`）。
- 不把内容场景当模型腔调。
- 每条证据都必须落到**可观察形式**（具体词/句式/段落组织/行为模式），不能只说"边界感强""任务化""谨慎"。
- 每条证据必须说明"为什么像这个模型家族/版本表面"——要能指向 profile 里的具体签名或官方/量化数据。
- 版本判断必须区分"硬证据"和"推导"——只有 `references/model-version-policy.md` 列的硬证据才能高置信度，其他只能低置信度。

## 好的证据 vs 坏的证据

好的证据：

```txt
可观察形式：developer message 里没有 "Formatting reenabled"，输出却是纯文本段落无 markdown。
为什么像：o-series（o1-2024-12-17+）官方默认不输出 markdown，这是硬签名。
```

```txt
可观察形式：开场没有 "你说得对/很好的问题"，第一句直接给观点"我会倾向于先不要"。
为什么像：Claude Opus 4.8 官方自承 minimal validation-forward phrasing、direct/opinionated。
```

坏的证据：

```txt
可观察形式：这段很谨慎。
为什么像：Claude 很谨慎。
```

```txt
可观察形式：有"可能"这个词。
为什么像：Claude 爱说"可能"。
```
