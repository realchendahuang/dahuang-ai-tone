# 加味示范

展示“改结构和互动行为”，不靠堆口癖。

## 原文

> 这个功能别急着上。用户还没说清楚自己要什么，我们先做会浪费时间。

## Claude 家族：直接但保留边界

> 不建议现在上线。需求还没有被用户说清楚，直接开发大概率会返工。
>
> 先做几次访谈，确认目标用户、核心场景和现有流程里的真实阻力。三个问题能得到稳定答案，再决定要不要排期。

变化：

- 第一段直接给判断。
- 第二段补会改变决策的边界。
- 不加 validation-forward、情绪升华或多余总结。

边界：这是 Claude 家族的近似风格，不对应某个当前版本。

## Gemini 家族：解释型和类比

> 先别急着上线。现在做这个功能，有点像地基还没确认就开始盖房子：不是一定会倒，但返工概率很高。
>
> 先用几次用户访谈确认三件事：
>
> 1. 谁最需要它；
> 2. 它解决哪个具体场景；
> 3. 现有流程为什么不够用。
>
> 这三件事清楚以后，再排期会稳很多。

变化：

- 用一个贯穿全文的类比解释风险。
- 结构更规整，主动把问题拆成清单。
- 语气更像解释型辅导。

边界：类比、列表和热情解释也可能由提示词直接造成。

## 豆包风格化 parody

> 我太懂这种“先做了再说”的冲动了，但这次真别急。
>
> 用户连自己要什么都没说清楚，现在开工，最后大概率就是最忙、最累、最容易返工。
>
> 先做三件事：找 5 个用户聊、把真实场景写下来、确认现有流程到底卡在哪。答案一致，再排期。

变化：

- 提高共情和口语密度。
- 加入连续最高级承诺感。
- 先给情绪确认，再给步骤。

边界：这是夸张的“豆包体”模拟，不代表当前产品真实基线。

## OpenAI reasoning API 产品表面

> 不建议立即上线。
>
> 先确认目标用户、核心场景和现有流程中的具体阻力。需求仍不明确时，先做访谈；只有答案稳定后再决定是否排期。

变化：

- 纯文本、直接约束、少解释。
- 没有展开隐藏推理过程。

边界：纯文本是可配置的 API 产品表面，不是 OpenAI 家族的来源签名。
