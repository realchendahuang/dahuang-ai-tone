# 风格证据与时效策略

这份文件约束“找味”和版本级“加味”。目标是提高可解释性，不是提高归因胆量。

## 三层模型

### 家族风格

跨多个输出反复出现的组织、语气或互动倾向。家族风格仍会被提示词、语言、任务和产品表面改变。

### 版本快照

具体模型、日期或官方样本表现出的风格。快照只描述当时样本，不能自动外推到后续版本。

### 产品表面

API、ChatGPT、Claude.ai、App、系统提示、Markdown 设置、后处理和安全策略共同形成的外观。产品表面可以压过家族风格。

## 证据等级

从强到弱：

1. **受控同提示样本**：同一输入、明确模型快照、可复核原始输出。
2. **官方自述或官方示例**：能证明某个版本或产品行为，但不自动构成未知文本的识别签名。
3. **多来源重复观察**：独立社区、媒体或评测反复出现的相似现象。
4. **单一观察或口癖清单**：只用于生成灵感，不用于归因。

官方“如何提示模型”描述的是交互建议，不等于模型输出必然具有某种文风。API 的格式默认值描述产品行为，也不等于家族人格。

## 相似度规则

- **低**：只有通用模式、单一口癖或单一格式特征。
- **中**：至少两个不同类别的家族特征同时出现，并排除了最明显的场景解释。
- **高**：只用于已知来源的受控同提示样本比较；未知文本不输出高相似度。

不要把多个同类词汇堆在一起当作多个证据。“delve + tapestry + robust”仍然只是一个词汇层证据。

## 竞争解释

每次找味至少考虑一个替代解释：

- 用户提示明确要求列表、简洁、共情或无 Markdown。
- 文本经过人工编辑、翻译、摘要或模板拼接。
- 行业体裁本来就正式、结构化或术语密集。
- 多个模型共享同一通用 AI 模式。
- 产品表面或系统提示覆盖了模型家族倾向。

如果竞争解释同样合理，输出“无法区分”比强行选家族更好。

## 时效规则

- 静态 Skill 不使用“当前默认”“最新模型”“现在就是这种味”等无日期表述。
- 用户指定具体版本时，先确认名称、日期和官方页面是否仍存在。
- 找不到当前资料时，称为“历史快照”或“近似模拟”，不要补全想象。
- 更新资料时记录访问日期，并优先保留原始官方页面或受控样本。
- 版本事实超过一个发布周期后，重新核对再使用。

OpenAI 官方提示工程文档明确提醒：同一家族的不同模型快照也可能表现不同，并建议用固定快照和评测监控行为。因此，任何“版本味”都应当被当作快照，而不是永久人格。

OpenAI reasoning best practices 中关于 Markdown 的说明限定在特定 API reasoning models 与 developer message 配置；它是产品表面证据，不能仅凭无 Markdown 输出反推模型。

## 报告用语

推荐：

- “这段在组织方式上与 Claude 家族的某些样本相似。”
- “无 Markdown 更可能是提示或 API 表面，不能单独区分家族。”
- “目前只有词汇层弱信号，无法区分 GPT、Claude 与 Gemini。”
- “下面按历史版本快照近似模拟，不代表当前模型的稳定表现。”

避免：

- “这就是 Claude 写的。”
- “90% 是 GPT。”
- “出现这个词一定是 Gemini。”
- “这是某版本的硬签名。”
