## 同一意思不同风格怎么写（推导，无同 prompt 对照）

> 这是基于特征库的推导，不是真实同 prompt 对比。真实同 prompt 对比样本缺失，是当前最大空白。

假设要表达"这个功能现在不适合直接上线，建议先做用户访谈"：

### GPT 风格 [推导]

```txt
结论是：这个功能现在不适合直接上线。原因有三点：第一，用户需求还没有被验证；第二，直接开发会增加返工成本；第三，先做访谈能更快判断真实优先级。下一步可以先找 3-5 个用户确认场景。
```

特征：结论先行 → 分点（3 点带"第一/第二/第三"）→ 任务化下一步。

### Claude 4.8 [推导]

```txt
不建议直接上线。当前信息不足以支撑排期——先做 3-5 个用户访谈能更快判断真实优先级，也能避免返工。
```

特征：无 validation-forward 开场、直接给观点、emoji 克制、收尾不啰嗦。

### Claude 3.x [推导]（历史版本）

```txt
我会倾向于先不要急着上线。但这不一定意味着这个功能没有价值，而是说在当前信息还不充分的情况下，直接推进可能会带来额外成本。更稳妥的做法，是先明确用户真正想解决的问题。
```

特征：先承认合理性 → hedging（"倾向于/不一定意味着/更稳妥"）→ 温和可商量的下一步。

### Gemini [推导]

```txt
在决定是否上线新功能前，可以从三个方面评估：用户需求是否明确、实现成本是否可控、上线后是否能衡量效果。这个流程有助于降低返工风险，并提升产品决策质量。
```

特征：知识卡片化、定义先行、分点密集、中性教育式、规整收束。

### 中文模型 [推导]

```txt
建议你先不要急着上线这个功能。可以先和用户确认一下真实需求，再看看现有流程里是不是有更优先要修的地方。这样会更稳，也能减少后面反复调整的成本。
```

特征：亲和顺滑、"你可以先……再……"建议结构、中文产品助手感。
